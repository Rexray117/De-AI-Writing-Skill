# 六类病灶细则

每类给：识别特征 → 为什么刺眼 → 改法步骤 → 易犯的错。改写时按顺序查，命中哪类翻哪节。

---

## 1 堆叠定语

**识别特征**

- 「可配置、可追溯、可回滚」式三连以上并列
- 同一名词前挂三个以上形容词，中间用顿号或「又…又…」
- 卖点串烧：把功能、特性、形容混在一句里
- 「真正懂你」「一站式」「全链路」这类收尾形容词

**为什么刺眼**

定语是防御性修辞。写的人怕漏卖点，全挂上去，读者拿到的是一串形容词而不是一个事实。检查方法极简单：把定语逐个删掉，如果删掉后读者对产品的判断没变，那它就是装饰。

**改法步骤**

1. 拆句：一个定语变成一句事实，主语是"它"，谓语是具体动作。
2. 留最硬的一个：三个定语里通常只有一个可验证（可回滚），其余是评价（高效、智能）。
3. 数字替换形容词：「高实时」→「200ms」；「高可用」→「双活，切换 30 秒内」。
4. 营销腔只留标题层，正文一律落到可验证陈述。

**易犯的错**

把「可 A 可 B 可 C」改成「既 A 又 B 还 C」——结构换了，病没走。

## 2 小剧场

**识别特征**

- 给一个动作补写动机、画面、后果：「点击后系统会立即响应，让你无需等待」
- 「只要…就…，不用…就…」的双段式条件句
- 描述性的连续动作链：谁看到什么、感到什么、于是怎样
- 注释、参数说明、操作步骤里出现"让用户…"「你会发现…」

**为什么刺眼**

读者在找操作路径，作者在演一幕戏。信息密度被摊薄，而且戏里的人物情绪是模型想象的，跟真实用户没关系。

**改法步骤**

1. 还原成三段：条件 → 动作 → 结果。缺哪段问哪段，别补。
2. 动词落在具体对象上：「返回校验结果」，不写「让你无需等待就能看到结果」。
3. 时间、数量、位置能填就填：200ms、右上角、30 天。
4. 判据：改后如果比原来短一半而信息没少，原句就是戏。

**易犯的错**

删掉画面但留下"让用户"——「让用户体验到流畅」仍是戏，只是短了一点。

## 3 否定递进

**识别特征**

- 「不只是 X，而是 Y」「不仅是 X，更是 Y」「不是 X，而是 Y」
- 「这哪是 X，这分明是 Y」「与其说 X，不如说 Y」
- 先立一个没人主张的 X，再打掉它抬高 Y
- 句式内部前后不搭：被否定的 X 和后半句的 Y 根本不是一回事

**为什么刺眼**

被否定的那半句往往没人说过，读者要花一秒去反驳一个不存在的主张。这类句子还有个副作用：为了凑句式，X 会被随手编出来，导致前后逻辑断开。

**改法步骤**

1. 先问：谁把 X 说成 X 了？答不出，删掉整个否定，只留 Y。
2. 真需要对比时，把 X 写成真实存在的替代方案，并给出选它的代价。
3. 全篇上限一次，且必须在真的有人主张过 X 的场合。
4. Y 单独成句后要能站住：如果「更是一套决策支持体系」单独看是空话，那说明问题不在句式，在于这句本来没内容。

**易犯的错**

把「不只是 A，更是 B」改成「A，而且 B」——递进关系没了，但 B 依然是空话。要先确认 B 有信息。

## 4 防御性语言

**识别特征**

- 「我们只是修改系统功能，不是重做整个系统」
- 「不能代表」「不能说明」「不能宣称」「不意味着」「不代表」
- 「需要注意的是」「必须指出」「在此特别说明」
- 每段末尾补一句限定，同一免责换三种说法重复

**为什么刺眼**

它同时踩两个坑：否定一个没人提的方案，再补一段没人要的免责。用户读到的潜台词是"我可能误解了，而且作者觉得我很蠢"。

**改法步骤**

1. 免责换成条件句，一句写完：写「在什么条件下成立」，不写「不能代表什么」。
   - 差：不能代表真实气象条件下的表现
   - 好：适用于 mock 数据；真实条件待验证
2. 同一段只设一次边界，后面默认继承，不重复。
3. 合规必需的集中在文末「适用范围」，不要每段撒。
4. 判据升级版：把"不能 X"改写成"能 Y"，读者拿到的是能力边界而不是否认。

**易犯的错**

以为写完条件句就完事，却在下一段又补一句"当然，这也不意味着……"。剔干净，一处就够。

## 5 对仗口号

**识别特征**

- 「一次 X，到处 Y」「一个 X，N 个 Y」「一套规则，多端复用」
- 两边字数刻意相等，读起来像广告语
- 数字排比：「一台手机，两个空间，互不干扰」
- 总分结构的口号化：一个总起，随后并列三到四条对称短句

**为什么刺眼**

对仗是修辞快感。为了让两边字数相等，作者被迫删掉重要限定、加上不重要的对称词。读者记住的是节奏，不是内容。

**改法步骤**

1. 拆开数：两边真是同一件事吗？不是就改写。
2. 口号留标题与封面，正文给对象、数量、路径。
   - 差：一次配置，全流程生效
   - 好：规则在后台配一次，PC 与移动端同时生效
3. 「一个 X，N 个 Y」要写清 N 具体是几、Y 具体是哪几个。
4. 真的只是并列清单时，用列表，别做成对仗句。

**易犯的错**

把两句对仗合并成一句长句——对仗感消失了，但信息仍是并列的，读者依旧不知道"多端"是哪几端。

## 6 吃定心丸

**识别特征**

- 「主动权始终在你」「随时可以修改或撤销」「不必担心」
- 「请放心」「尽管放心使用」「你的数据是安全的」
- 界面文案、代码注释、说明书里出现的心理疏导
- 一段里出现两处以上"随时可以…"

**为什么刺眼**

安抚情绪不解决问题。让人不安的从来不是"能不能改"，而是"改错了怎么回退、多久生效、谁看得见"。这类句子是模型把自己脑补出的用户恐惧写进了产品。

**改法步骤**

1. 把安抚换成事实四件套：入口在哪、能不能撤销、多久生效、影响谁。
2. 界面与注释不写心理疏导。
3. 一段出现第二处「随时可以…」，直接删。
4. 判据：改后的句子能不能被截图当说明书用？不能就还是安抚。

**易犯的错**

把「请放心」改成「无需担心」——同义替换，一个字都没变。

## 结构层病灶（词改完了还像 AI，查这十条）

1. **总分总闭环**：每节开头预告、结尾总结。删掉后正文仍成立，说明它们本就多余。
2. **三点式凑数**：凡事列三条。真实条目常常是两条或五条。
3. **段落等长**：每段三到四句，节奏像打字机。人的段落长短是乱的。
4. **小标题过密**：200 字一个小标题，说明没有连续论证的能力。
5. **列表替代论证**：因果关系被拆成 bullet，读者只看到并列，看不到推导。
6. **重复解释**：一句话说完，再用「也就是说」说一遍。
7. **长度通胀**：一句能说完的写成三句。测法：压缩一半，信息丢了没有。
8. **比喻通胀**：每段一个「就像…」。比喻越密，信息越薄。
9. **情绪通胀**：平淡事件写成剑拔弩张，日常对话写成对峙。
10. **视觉指纹**：网页左上角挂装饰性小标题、配色偏紫；文档里加粗密度过高、每段首句加粗。
