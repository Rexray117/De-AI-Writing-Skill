# 体裁总谱

中文写作不是一个体裁，是六个族。族决定骨架，骨架决定哪里能下刀。

先定族，再定子类，最后才看词。定错族，越改越远——把公文改得像公众号，是把合规文本改成事故。

---

## 三步定族

1. **读者要做什么？** 照做（技术、公文）／被说服（学术、商务）／被带走（叙事、宣传）。
2. **写错了谁负责？** 出事有法律或合规后果 → 公文族；事实错误会被追责 → 技术族、学术族；只损失观感 → 叙事族、宣传族。
3. **允许虚构吗？** 允许（人物、情节、场景）→ 叙事族；不允许 → 其余五族。

三问的答案组合基本唯一。组合冲突时，按"出错代价最大"的那一问定族。

---

## 六族总表

| 族 | 子类 | 骨架（必须有的部分） | 强度 | 施刀层 | 头号病灶 | 判定问句 |
|---|---|---|---|---|---|---|
| A 技术族 | PRD、接口文档、用户手册、运维手册、README、验收标准、ADR | 目标与范围 → 前提依赖 → 步骤或规则 → 边界与失败 → 变更记录 | 中 | L1+L2+L4 | 小剧场、防御性 | 读者能照着做出来吗 |
| B 学术族 | 期刊论文、学位论文、会议短文、综述、开题报告、实验报告、审稿回复 | IMRaD 或 问题-方法-结果-讨论，引用与图表编号 | 中 | L1+L2+L4 | 翻译腔、模板骨架 | 结论能被数据和引用支撑吗 |
| C 叙事族 | 网文连载、短篇、对话体、剧本、第一人称随笔、同人 | 场景 → 冲突 → 转折 → 留钩 | 强 | L1+L2+L3+L4 | 比喻通胀、情绪通胀 | 这一场戏非写不可吗 |
| D 宣传族 | Slogan、详情页、发布会稿、公众号推文、招聘 JD、海报文案、短视频脚本 | 钩子 → 利益点 → 证据 → 行动指令 | 强 | L1+L2+L3 | 堆叠定语、对仗口号 | 删掉这句，卖点还成立吗 |
| E 商务族 | 邮件、周报日报、汇报提纲、方案标书、简历、会议纪要 | 结论 → 依据 → 请求或下一步 | 强 | L0+L2+L4 | 吃定心丸、过度免责 | 收件人看完知道该做什么吗 |
| F 公文族 | 通知通报、请示批复、制度办法、合规声明、合同条款、法律意见 | 依据 → 事项 → 执行要求 → 生效与解释 | 弱 | L1(结构)+L4 | 不适用（只删重复） | 改动会不会改变法律含义 |

## A 技术族

**结构上的硬约束**：每个动作必须能被执行、被验证、被复现。所以"条件—动作—结果"三段不能省，缺哪段问哪段，不许补。

| 子类 | 骨架细节 | 特别禁止 |
|---|---|---|
| PRD | 背景与目标 → 用户与场景 → 功能清单（编号）→ 交互与状态 → 约束与非目标 → 验收 | 体验承诺、市场形容词、需求理由写成长篇论证 |
| 接口文档 | 路径与方法 → 鉴权 → 请求参数表 → 响应字段表 → 错误码 → 示例 | 字段说明里写业务故事 |
| 用户手册 | 前提 → 步骤（祈使句）→ 预期结果 → 失败处理 | 步骤里插解释、一句话三个动作 |
| 运维手册 | 环境 → 命令 → 校验方式 → 回滚 | 省略回滚、写"请注意安全" |
| README | 这是什么 → 怎么跑起来 → 目录结构 → 贡献方式 | 项目愿景、未来展望 |
| 验收标准 | 用例编号 → 前置 → 步骤 → 期望 → 实际 | "表现良好"式模糊判定 |
| ADR | 决策 → 背景 → 备选方案 → 取舍理由 → 后果 | 把决策写成宣传 |

技术族的"小剧场"最容易藏在字段说明和提示文案里：「点击后系统会立即响应，让用户无需等待」。字段表里只有一个位置：返回值。

## B 学术族

**结构上的硬约束**：章节功能不能换位。方法写方法，结果写结果，讨论才允许推测。综述可以重排逻辑，实验报告不许。

| 子类 | 骨架 | 特别提醒 |
|---|---|---|
| 期刊论文 | 摘要（目的-方法-结果-结论）→ 引言 → 方法 → 结果 → 讨论 → 结论 | 摘要里不出现"本文旨在"这类元叙述 |
| 学位论文 | 章 → 节 → 三级标题，前置目录与后置附录 | 章末小结可以有，但要给新信息 |
| 会议短文 | 问题 → 方法 → 关键结果 → 局限 | 局限段不许写成免责套话 |
| 综述 | 检索范围 → 分类框架 → 对比 → 空白点 → 展望 | 分类框架不许硬凑三份 |
| 开题报告 | 问题 → 现状 → 缺口 → 方案 → 计划 | 计划要有时间节点，不写"稳步推进" |
| 实验报告 | 目的 → 器材 → 步骤 → 数据 → 误差分析 | 数据表不许概括成"效果明显" |

**红线**：数字、DOI、PMID、年份、术语零改动。改文不改数据。

## C 叙事族

**结构上的硬约束**：每一场戏要推进至少一件事——信息、关系、处境，三者至少一个变。不推进的段落，删。

| 子类 | 节奏骨架 | 头号病灶 |
|---|---|---|
| 网文连载 | 开篇钩子 → 冲突升级 → 小高潮 → 章末留钩 | 章末升华、每段都短句 |
| 短篇小说 | 场景切入 → 张力累积 → 转折 → 余味 | 结尾总结主题 |
| 对话体／剧本 | 动作提示 + 台词，台词承担信息与性格 | 台词里塞解释、旁白式心理 |
| 第一人称随笔 | 具体事起 → 联想 → 回到事 | 强行抒情、金句结尾 |

叙事族允许 L3 重排，但人物设定、剧情走向、观点归属不许动。AI 短剧腔（指尖泛白、心跳漏拍、命运的齿轮）出现即换。

## D 宣传族

**结构上的硬约束**：每一条主张后面要跟得上证据。跟不上的，删主张，不删证据。

| 子类 | 骨架 | 特别禁止 |
|---|---|---|
| Slogan／标题 | 一个动词 + 一个对象，或一个反差 | 三个以上并列、四字堆叠 |
| 详情页 | 场景痛点 → 能力 → 参数证据 → 价格与保障 | 编造用户评价与销量 |
| 发布会稿 | 一个主张 → 演示 → 对比 → 价格与时间 | "重新定义""颠覆" |
| 公众号推文 | 具体事件切入 → 展开 → 收在一个判断上 | 结尾"未来可期" |
| 招聘 JD | 业务一句话 → 职责（动词开头）→ 要求（可验证） | "有激情""抗压能力强" |
| 短视频脚本 | 前三秒冲突 → 论证 → 行动指令 | 空镜配空话 |

**红线两条**：不得虚构数据、资质、案例；广告法禁用语（最、第一、国家级、顶级）不得出现。

## E 商务族

**结构上的硬约束**：收件人读完要知道下一步做什么。没有下一步的商务文本，多半不该发。

| 子类 | 骨架 | 特别禁止 |
|---|---|---|
| 邮件 | 事由 → 需要对方做什么 → 时限 | 客套开场、免责三连 |
| 周报 | 本周完成（数字）→ 卡点 → 下周计划 | "稳步推进""持续优化" |
| 汇报提纲 | 结论 → 三条依据 → 需要的决策 | 每页都要小结 |
| 方案／标书 | 理解 → 方案 → 实施 → 报价 → 案例 | 形容词堆砌代替案例 |
| 简历 | 动作 + 对象 + 量级 | 自我评价段、对仗成果句 |
| 会议纪要 | 决议 → 责任人 → 时间 | 记录发言过程 |

## F 公文族

**不套本技能的词表。** 法定表述、限定语、条款顺序都是义务。

| 子类 | 只做这些 |
|---|---|
| 通知／通报 | 拆超长句、合并重复的过渡语 |
| 请示／批复 | 保留全部依据引述 |
| 制度办法 | 不改条款层级与编号 |
| 合规声明／合同 | 不动任何限定与免责 |
| 法律意见 | 不动，只标格式问题 |

交付时说明一句：属公文/合规语体，仅做结构层调整。

## 交叉与混合

一份文档里常有多种体裁：白皮书（技术+宣传）、PRD 里的营销页需求、招聘 JD（商务+宣传）、案例研究（学术+商务）。

**裁决规则：按段落判，不按整篇。** 判断依据是这段最容易被谁引用——被工程师引用的按技术标准，被市场引用的按宣传标准。

混合时在改动表里分栏标注，不要用一种标准压全篇。同一份文档里，PRD 正文的"不写体验承诺"和营销页的"必须写利益点"可以同时成立。

## 一张对照表（同一件事，六种写法）

事实：风险等级模块支持阈值配置，改错了能回滚，加载 300ms。

| 族 | 写法 |
|---|---|
| 技术 | 阈值可在配置页修改；改动写入配置历史，支持一键回滚；首屏加载 300ms（本地缓存）。 |
| 学术 | 阈值配置采用可回滚设计（附录 B 给出状态机），实测首屏加载 300ms（n=30，本地缓存）。 |
| 叙事 | 他把阈值从 8 调到 6，屏幕上跳出一行小字：已记录，可回滚。 |
| 宣传 | 调错了？一秒退回上一版。 |
| 商务 | 阈值配置已上线，改动可回滚；建议本周验收，下周一发布。 |
| 公文 | 各项目应于本通知印发之日起在系统内完成阈值配置，配置变更须留存记录。 |

同一事实，六种骨架，六种句子长度。这就是"适用范围"的实际含义。
