# 四层分工与验收

## 层与层之间靠什么衔接

每层的输出是下一层的输入，且每层都可以独立验收。跳层只在一种情况下允许：用户只要诊断（只跑 L1）。

| 层 | 回答的问题 | 手段 | 输出 | 验收 | 可回退 |
|---|---|---|---|---|---|
| L0 判据 | 这句该不该存在 | 三问 + 删句测试 | 删/留/改的决策 | 删完读者不缺信息 | — |
| L1 检测 | 味在哪 | 词表、正则、结构统计 | 命中清单 + 评分卡 | 分数可复现 | 不改原文 |
| L2 句面改写 | 怎么说才像人 | 六病灶 + 三刀 | 改后正文 | 重扫 ≤7 分；guard 通过 | 逐句可回退 |
| L3 结构重构 | 整篇怎么组织 | 换入口、乱节奏、留摩擦 | 重排后的正文 | 信息无损；叙事得体 | 需保留原稿 |
| L4 完整性守卫 | 有没有改坏事实 | 数字/编号/引用/术语比对 | PASS 或 FAIL 清单 | 退出码 0 | 强制回退到 L2 |

**L4 不是最后一层，是护栏。** 它贯穿 L2 与 L3，每次改完都要过。学术与合同类文本，L4 的优先级高于 L2——宁可留着 AI 味，也不能把 30% 改成 20%。

## 强度三档

强度不是"改多少"，是"允许动到哪一层"。

| 档 | 允许动 | 适用 | 典型动作 |
|---|---|---|---|
| 弱 | L1 结构项 + L4 | 公文、合规、法律、医疗说明 | 删重复的串场词、拆超长句 |
| 中 | L1 + L2 + L4 | PRD、技术文档、报告、学术 | 六病灶清理 + 三刀 |
| 强 | L1 + L2 + L3 + L4 | 小说、公众号、产品文案、邮件 | 加上重排与节奏 |

判断强度只看一件事：**结构本身是否承载语义**。PRD 的章节顺序就是需求顺序，学术的 IMRaD 是评审预期，公文的三段式是格式要求——这三种都不许动。

## 三种入口的完整路径

### 入口一：拿到一份 AI 稿，要求去味

1. 定体裁（`genre-rules.md`），拿强度档。
2. `scan.py` 出评分卡，记下基线分。
3. L0 逐段过三问，先批量删。
4. L2 六病灶对症 + 三刀。
5. `guard.py` 比对原稿，确认数字术语没动。
6. 重扫，分数必须降；不降说明改动没打在病灶上，回去看命中清单。
7. 交付三块（正文 + 改动表 + 验证结果）。

### 入口二：从零代写

1. 先读 `lexicon.md` 末节的禁令块，写之前就守。
2. 写完跑 `scan.py`，≥7 分就回改。
3. 交付只给正文，不附自评。

从零写的时候最容易犯的不是六病灶，是结构：每节都收束、每段都三句、凡事列三点。

### 入口三：只要验收（用户已自行改完）

1. `scan.py` 出分。
2. `guard.py` 比对原稿与改稿。
3. 输出两项结论，附最该回改的 3 条。不改正文。

## 验收的硬标准

- **信息**：删句之后读者不缺信息；数字、术语、引用零变动。
- **节奏**：段落句数不整齐；没有连续三段同长度。
- **句式**：没有「不只是 X，而是 Y」的假靶子；没有给简单操作补画面。
- **姿态**：读起来是"一个懂行的人在说事"，不是"导师在教学生"，也不是"客服在安抚"。
- **诚实**：没有为了好看而新增的事实、数据、案例。

最后一条最难自动化，也最容易被忽略。去 AI 味的终点不是"检测器放行"，是读者愿意读完。
