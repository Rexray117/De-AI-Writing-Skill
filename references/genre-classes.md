# 七大类文体路由

中文写作不是一个体裁。这份文件按《文章分类》把四十余个子类划成七大类，每类给：读者要什么、去 AI 味优先级、头号病灶、映射到六族体系后的强度档。族级骨架与允许度再看 `genre-taxonomy.md` 与 `genre-rules.md`。

三步定族（判错族，越改越远）：

1. **读者要做什么？** 照做（实用说明、法规）／被说服（专业论证、商务）／被带走（叙事、营销、社交）。
2. **写错了谁负责？** 有法律合规后果 → 法规制度类；事实被追责 → 实用说明、专业论证；只损观感 → 其余四类。
3. **允许虚构吗？** 允许 → 叙事创作类；不允许 → 其余六类。

三问冲突时，按"出错代价最大"的那一问定族。

---

## 一、实用说明类 → A 技术族（强度：中）

读者要的是"看完能操作、能查到、能排错"。这类文本里 AI 腔约等于不专业。

| 子类 | 典型载体 | 去 AI 味优先级 | 头号病灶 |
|---|---|---|---|
| 产品需求文档 PRD | 飞书/Confluence | 中 | 小剧场、防御性语言 |
| 接口文档 / API 文档 | 开发者文档站 | 中 | 堆叠定语、模板骨架 |
| 用户手册 / 操作指南 | 帮助中心、PDF | 中 | 小剧场、吃定心丸 |
| 运维手册 / 故障 SOP | 内部 Wiki | 中 | 防御性语言、元叙述 |
| README / 开源说明 | GitHub、Gitee | 低–中 | 对仗口号、堆叠形容词 |
| 验收标准 / 测试用例 | 项目文档 | 低 | 模板腔 |
| FAQ / 客服话术库 | 帮助页、机器人 | 中 | 吃定心丸、防御性语言 |
| 产品功能详细介绍 | 产品站、交付文档 | 中 | 宣传腔混入技术说明 |

中文特有点：帮助中心和产品功能说明最容易夹带"一键操作、简单易上手、小白也能用"的吃定心丸句式；PRD 最容易在"背景"段落写成宣传稿。

## 二、专业论证类 → B 学术族（强度：中）

读者要的是证据链和判断，不是情绪。AI 腔在这里主要表现为"模板骨架"和"翻译腔"，而不是口语化。

| 子类 | 典型载体 | 去 AI 味优先级 | 头号病灶 |
|---|---|---|---|
| 期刊论文 / 学位论文 | 知网、投稿系统 | 高（学术模式） | 翻译腔、模板骨架 |
| 开题报告 / 文献综述 | 学校系统 | 高 | 模板骨架、堆叠引用 |
| 实验报告 / 调研报告 | 内部或公开 | 中 | 模板骨架、过度总结 |
| 白皮书 / 行业报告 | 机构官网 | 中–高 | 对仗口号、堆叠定语 |
| 方案标书 / 投标文件 | 招投标平台 | 中 | 防御性语言、对仗口号 |
| 商业计划书 / BP | 投资机构 | 中 | 吃定心丸、堆叠形容词 |
| 竞品分析 / 产品分析 | 内部、公众号 | 中 | 小剧场、否定递进 |
| 学术会议短文 / 海报 | 会议系统 | 高 | 翻译腔、模板骨架 |

中文特有点："随着……的发展""在……背景下"是论文和标书的典型模板骨架；白皮书最容易被写成"赋能、重塑、引领"的发布会稿。

## 三、商务事务类 → E 商务族（强度：强）

读者要的是结论、责任人和下一步。AI 腔的代价是"看起来说了很多，实际没有信息"。

| 子类 | 典型载体 | 去 AI 味优先级 | 头号病灶 |
|---|---|---|---|
| 工作邮件 | 企业邮箱 | 高 | 防御性语言、吃定心丸 |
| 周报 / 日报 | 飞书、钉钉、企微 | 高 | 对仗口号、过度总结 |
| 汇报提纲 / 述职报告 | PPT、文档 | 中–高 | 对仗口号、堆叠形容词 |
| 会议纪要 | 内部文档 | 高 | 元叙述、过度总结 |
| 项目复盘 / 结项报告 | 内部文档 | 中 | 过度总结、防御性语言 |
| 简历 / 求职信 | 招聘平台 | 高 | 堆叠形容词、对仗口号 |
| 内部通知 / 公告 | 企微、OA | 中 | 模板腔、吃定心丸 |
| 跨部门协作说明 | IM、文档 | 中 | 防御性语言、小剧场 |

中文特有点：周报和简历是"对仗口号"重灾区（"负责……推动……赋能……"）；邮件最容易写成"不是……而是……"的防御性长段。

## 四、营销转化类 → D 宣传族（强度：强）

读者要的是利益点和行动理由。对 AI 腔最敏感，因为读者滑走成本为零。

| 子类 | 典型载体 | 去 AI 味优先级 | 头号病灶 |
|---|---|---|---|
| 公众号文章 | 微信公众号 | 高 | 对仗口号、小剧场 |
| 小红书笔记 | 小红书 | 高 | 小剧场、堆叠定语 |
| 抖音 / 视频号口播稿 | 短视频 | 高 | 对仗口号、否定递进 |
| 知乎回答 / 专栏 | 知乎 | 高 | 摆架势开场、假深沉格言 |
| 带货文案 / 直播话术 | 电商、直播间 | 高 | 堆叠定语、吃定心丸 |
| 产品详情页 | 电商、官网 | 高 | 堆叠定语、对仗口号 |
| 品牌 Slogan / TVC | 广告投放 | 中 | 对仗口号、空洞大词 |
| 招聘 JD | 招聘平台 | 中 | 对仗口号、堆叠形容词 |
| 新闻稿 / 软文 | 媒体、公关 | 中–高 | 宣传腔、模糊归因 |
| 活动预告 / 报名页 | 活动平台 | 中 | 吃定心丸、对仗口号 |

中文特有点：公众号和小红书有固定套路——开场制造悬念、中段三段排比、结尾"未来已来"；直播话术和详情页集中在"可 A 可 B 可 C"的堆叠定语；"不是 A 而是 B"和"这哪是 X，这分明是 Y"在此高发。

## 五、叙事创作类 → C 叙事族（强度：强，允许 L3）

读者要的是人物、场景和冲突。"人味"最值钱的地方，也是唯一允许结构重排的类别。

| 子类 | 典型载体 | 去 AI 味优先级 | 头号病灶 |
|---|---|---|---|
| 网络小说连载 | 起点、晋江、番茄 | 高 | 比喻通胀、情绪通胀 |
| 短篇小说 / 文学投稿 | 期刊、平台 | 高 | 假深沉格言、比喻通胀 |
| 剧本 / 短剧脚本 | 影视、短剧平台 | 高 | 情绪通胀、模板对白 |
| 人物特稿 / 非虚构 | 媒体、公众号 | 高 | 摆架势开场、过度总结 |
| 随笔 / 散文 | 博客、公众号 | 高 | 假深沉格言、单行收尾 |
| 对话体 / 访谈整理 | 播客、媒体 | 中–高 | 元叙述、过度总结 |
| 儿童故事 / 绘本 | 出版、教育 | 中 | 堆叠形容词、说教结尾 |
| 游戏剧情 / 世界观 | 游戏内、设定集 | 中 | 堆叠定语、模板骨架 |

中文特有点：网文和短剧的 AI 腔集中在"情绪通胀"（每个动作都配心理描写）与"比喻通胀"（每段都打比方）；非虚构和随笔容易写成"摆架势开场 + 假深沉金句收尾"。可以动结构，但前提是用户明确说"重写"。

## 六、社交表达类 → D/C 短打（强度：强）

读者要的是"这个人怎么想"，不是完整论证。短、碎、依赖语境。

| 子类 | 典型载体 | 去 AI 味优先级 | 头号病灶 |
|---|---|---|---|
| 微博 / 短动态 | 微博、即刻 | 高 | 假深沉格言、对仗口号 |
| 朋友圈文案 | 微信 | 高 | 小剧场、吃定心丸 |
| 知乎评论 / 回答 | 知乎 | 中–高 | 摆架势开场、否定递进 |
| B 站动态 / 视频简介 | B 站 | 中 | 对仗口号、堆叠形容词 |
| 社群消息 / 群公告 | 微信群、QQ 群 | 中 | 吃定心丸、模板腔 |
| 评论区互动 / 弹幕 | 各平台 | 中 | 小剧场、模板对白 |
| 个人签名 / 简介 | 各平台 | 低–中 | 假深沉格言、堆叠定语 |

中文特有点：朋友圈和小红书共享"小剧场"病灶；微博和知乎的 AI 腔更多是"摆架势"——先否定一个常见说法，再给出看似深刻的判断。

## 七、法规制度类 → F 公文族（强度：弱，豁免词表）

读者要的是依据、事项、执行和生效。几乎不追求"人味"，追求准确和可追溯。

| 子类 | 典型载体 | 去 AI 味优先级 | 头号病灶 |
|---|---|---|---|
| 合同 / 协议 | 法务系统、纸质 | 低（只删重复） | 不适用 |
| 法律意见书 | 律所、法务 | 低 | 不适用 |
| 合规声明 / 隐私政策 | 官网、App | 低–中 | 模板腔、防御性语言 |
| 公司制度 / 管理办法 | 内部 OA | 低 | 模板腔、重复 |
| 政府公文（通知/请示/批复/函） | 政务系统 | 低（豁免词表） | 不适用 |
| 行政处罚 / 许可文书 | 政务系统 | 低 | 不适用 |
| 行业标准 / 团体标准 | 标准发布平台 | 低 | 模板腔 |

中文特有点：公文族有固定格式和套语，AI 腔在这里不是"太像 AI"，而是"格式不对、事项不清"。去 AI 味只做重复删除和结构核对，不追求口语化。

## 混合文体

一份文档常有多种体裁：白皮书（实用+论证）、PRD 里的营销页需求、招聘 JD（商务+营销）、案例研究（论证+商务）、公众号软文（营销+叙事）。

**按段落判，不按整篇。** 判断依据是这段最容易被谁引用——被工程师引用的按技术标准，被市场引用的按营销标准，被法务引用的按法规标准。混合时在改动表里分栏标注，不用一种标准压全篇。

## 同一事实，七种写法

事实：风险阈值模块支持配置，改错了能回滚，加载 300ms。

| 类 | 写法 |
|---|---|
| 实用说明 | 阈值可在配置页修改；改动写入配置历史，支持一键回滚；首屏 300ms。 |
| 专业论证 | 阈值配置采用可回滚设计（附录 B 状态机），实测首屏加载 300ms（n=30）。 |
| 商务事务 | 阈值配置已上线，改动可回滚；建议本周验收，下周一发布。 |
| 营销转化 | 调错了？一秒退回上一版。 |
| 叙事创作 | 他把阈值从 8 调到 6，屏幕跳出一行小字：已记录，可回滚。 |
| 社交表达 | 试了下新后台，阈值调错居然能一键退回，省心了。 |
| 法规制度 | 各项目应于本通知印发之日起完成阈值配置，配置变更须留存记录。 |
